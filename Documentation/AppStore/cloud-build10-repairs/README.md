# Xcode Cloud Build 10 diagnosis and repairs

Build 10 used main commit `4ef419190136e9ce253a729def7fbfd767ede622`. Apple’s action issues and downloaded build logs establish:

- iOS and visionOS failed destination validation before tests ran: the selected devices were reported unsupported by the `default` runtime. Xcode 27.1 RC metadata advertises explicit `com.apple.CoreSimulator.SimRuntime.iOS-27-1` and `com.apple.CoreSimulator.SimRuntime.xrOS-27-0` runtimes for these devices. `workflow-runtime-patch.json` records explicit destination selections, retaining all required tests and archives; the API returned HTTP 405 on PATCH. The iOS and visionOS pins were then saved through App Store Connect and independently verified via API. Other actions and main triggers are unchanged.
- Mac build-for-testing used `CODE_SIGN_IDENTITY=-` while embedding associated-domains, declared-age-range, and group-session production entitlements. Its runner failed to launch, before tests or coverage could execute. GitHub already uses an ad-hoc-compatible sandboxed unit host. The new Cloud pre-build hook applies that same entitlement set only to macOS build-for-testing. Production archives and other platforms retain their signing configuration. This addresses a concrete configuration discrepancy; a new Cloud run must confirm launch acceptance. The logs also show the beta macOS builder selecting arm64e from multiple destinations. Although the broad API inventory includes stable macOS 27, the workflow UI offers only the selected beta builder for this Xcode RC. Its Mac destination is retained; architecture selection remains an Apple-service warning.
- Compiler warnings: remove an unnecessary `try`, remove actor isolation from a stateless synchronous test coordinator, explicitly discard two drag-order results and a test fixture’s persisted-record result.
- visionOS renderer: use typed pixel-buffer attributes, read-only frame extraction, and the OS 27 render-synchronizer receiver for enqueue/flush. Keep its clock aligned with playback rate, including pause and seek. Production stereoscopic rendering still needs runtime acceptance.
- The missing coverage-profile warning is downstream of the Mac runner launch failure; no tests produced profiles. Coverage remains enabled. The multiple-matching-Mac-destinations warning comes from Apple’s generic destination invocation, not an app compiler warning.

Validation: 13 Cloud bootstrap/pre-build tests pass, including archive preservation and exact sandbox/network-only test entitlements. SwiftFormat and project/pin consistency pass. The modified visionOS renderer type-checks against Xcode 27.1 RC’s visionOS 27 SDK with warnings as errors. No full application builds, device installs, or Git pushes were performed locally. Full Cloud acceptance must follow the user’s remote push.

Apple references: [environment variables](https://developer.apple.com/documentation/xcode/environment-variable-reference), [custom build scripts](https://developer.apple.com/documentation/xcode/writing-custom-build-scripts). Runtime inventory and failure evidence were obtained through the authenticated App Store Connect API; raw downloaded logs remain in temporary storage.
